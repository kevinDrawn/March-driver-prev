# MAQ473 엔코더 캘리브레이션 & 위치제어 검증 보고서

## 1. 프로젝트 개요

### 시스템 구성
- **MCU**: STM32G431 (170MHz Cortex-M4F)
- **모터 드라이버**: DRV8316 (3상 게이트 드라이버)
- **모터**: maxon EC-i 460720 (BLDC, 7 pole pairs)
- **엔코더**: MAQ473 (자기식 앱솔루트 엔코더, 14bit)
- **제어**: SimpleFOC 라이브러리 기반 FOC (Field Oriented Control)
- **토크 제어 방식**: Voltage mode (전류 센싱 없이, q축 전압으로 토크 제어)

### 목표
MAQ473 엔코더의 비선형 오차를 LUT(Look-Up Table)로 보정하고, 위치제어 PID를 튜닝하여 **서브-도 수준의 반복성**을 달성하는 것.

## 2. 엔코더 캘리브레이션 (LUT 보정)

### 2.1 왜 LUT 보정이 필요한가?

자기식 엔코더(MAQ473)는 자석이 회전할 때 생기는 자기장의 변화를 측정하여 각도를 계산합니다. 하지만 다음과 같은 이유로 **체계적 비선형 오차**가 발생합니다:

- 자석의 **자화 불균일** — 자석이 완벽한 쌍극자가 아님
- 센서 IC와 자석 사이의 **기계적 오정렬** (편심, 기울기)
- **온도 특성** — 자석의 자화 강도가 온도에 따라 변함

이 오차가 보정되지 않으면:
- FOC 전류 벡터가 최적 각도에서 벗어남 → **토크 리플 증가**
- 위치제어 시 **위치 의존적 편차** 발생 (어떤 각도에서는 정확하고, 어떤 각도에서는 부정확)
- 같은 크기의 스텝 명령이라도 시작 각도에 따라 다른 성능

### 2.2 캘리브레이션 데이터 수집

외부 기준 엔코더(4096 inc/rev)를 모터축에 연결하고, 모터를 16스텝 × 22.5° = 360°(1회전) 이동시키면서 MAQ473의 출력을 100Hz로 기록했습니다.

- 각 스텝에서 모터가 **수렴할 때까지 대기(~3초)** 후 안정된 값의 평균을 채택
- 총 **6,729 샘플**, 67.3초 기록
- 누적 오차: **+0.004°** — 1회전 후 시작점과 거의 정확히 일치 (누적 드리프트 없음)

### 2.4 LUT 생성 과정

16개의 측정 오차를 128개 슬롯의 LUT(Look-Up Table)로 변환하는 과정:

```
[Step 1] 16개 측정 포인트 (각도, 오차) 쌍 추출
    ↓
[Step 2] 주기적 경계 처리 (360° = 0°이므로 양 끝을 연결)
    ↓
[Step 3] PCHIP 보간 → 128개 등간격 포인트로 확장
    ↓
[Step 4] 라디안 변환 → 펌웨어 헤더 파일 (sensor_lut_128.h) 생성
```

**실시간 적용**: 펌웨어의 `applyLUT()` 함수가 매 FOC 루프마다:
1. 현재 센서 각도로 LUT 슬롯 인덱스 계산 (128슬롯 = 2.8125° 간격)
2. 인접 두 슬롯 사이를 **선형 보간**하여 정확한 보정값 산출
3. `보정된 각도 = 원시 각도 - LUT 보정값`

**LUT 값이 측정 오차와 일치하는지 검증:**

| 측정 위치 (°) | 측정 오차 | LUT 값 | 차이 |
|------------|---------|--------|------|
| 46.21 | +0.000 | +0.000 | 0.000 |
| 137.28 | +1.076 | +1.074 | 0.002 |
| 228.06 (최대) | +1.858 | +1.858 | 0.000 |
| 293.62 | -0.087 | -0.084 | -0.003 |

→ 측정 포인트에서 LUT와의 최대 차이 **0.003°** — PCHIP이 측정 포인트를 정확히 통과합니다.

### 2.5 CubicSpline vs PCHIP — 보간 알고리즘 선택이 결정적이었던 이유

16개의 측정 포인트를 128개로 늘리는 보간(interpolation)에서 알고리즘 선택에 따라 성능이 극적으로 달라졌습니다.

**문제**: 16개는 128개 대비 너무 sparse합니다 (8슬롯마다 1개). 측정 포인트 **사이**의 보간 정밀도가 최종 LUT 품질을 결정합니다.

#### CubicSpline (기존 — 실패)
- **원리**: 모든 포인트를 지나면서 2차 도함수까지 연속인 3차 다항식. "가장 부드러운" 곡선을 생성.
- **문제**: 포인트 사이에서 **오버슈트** 발생. 예: 두 측정 포인트가 +1.63°, +1.74°인데, 중간에서 +2.5°까지 올라갔다 내려옴.
- 16개처럼 데이터가 sparse하면 이 오버슈트가 심각해짐.

#### PchipInterpolator (수정 — 성공)
- **원리**: Piecewise Cubic Hermite Interpolating Polynomial.
- **핵심**: 데이터의 **단조성(monotonicity)을 보존** — 두 포인트 사이에서 절대 오버슈트하지 않음.
- 대신 2차 도함수 연속성은 포기 (CubicSpline은 보장). 하지만 LUT 보정에는 1차 도함수 연속이면 충분.

## 3. 위치제어 PID 튜닝

### 3.1 제어 구조 이해

SimpleFOC의 각도 제어는 **캐스케이드(cascade) PID** 구조입니다. 두 개의 제어 루프가 중첩되어 있습니다:

```
[Target Angle] → [Angle P] → [Velocity PID] → [Voltage Vq] → [Motor]
                                                                 ↓
                              [Velocity ←─── Angle ←──── Encoder]
```

- **외부 루프 (Angle P)**: "현재 위치에서 타겟까지 얼마나 떨어져 있는가" → 필요한 속도를 계산 (P 제어만)
- **내부 루프 (Velocity PID)**: "현재 속도가 목표 속도와 얼마나 다른가" → 필요한 전압 Vq를 계산 (PID 제어)
- **Vq**: FOC에서 토크를 발생시키는 q축 전압. Vq가 클수록 모터가 강하게 회전.

왜 2단 구조인가? 직접 "각도 오차 → 전압"으로 제어하면 모터가 빠르게 회전할 때 제동이 어렵습니다. 속도 루프가 중간에서 "너무 빠르면 브레이크"를 걸어주는 역할을 합니다.

### 3.2 각 파라미터의 역할 — 무엇을 조절하는가

| 파라미터 | 한마디 설명 | 높이면 | 낮추면 |
|----------|------------|--------|--------|
| **velP** (Velocity Proportional) | "속도 오차에 즉각 반응하는 정도" | 빠르지만 진동 위험 | 느리고 안정적 |
| **velI** (Velocity Integral) | "누적 오차를 제거하는 힘" | 정상상태 오차 ↓, 진동 위험 ↑ | 정상상태 오차 ↑ |
| **velD** (Velocity Derivative) | "급격한 변화를 억제하는 댐퍼" | 오버슈트 ↓, 노이즈 민감 | 오버슈트 ↑ |
| **angP** (Angle Proportional) | "위치 오차를 속도 명령으로 변환하는 비율" | 빠른 초기 응답 | 느린 응답 |
| **output_ramp** | "Vq(전압)가 변할 수 있는 최대 속도" | 빠른 가감속 | 부드러운 시작/정지 |
| **velocity_limit** | "모터의 최대 허용 회전 속도" | 큰 스텝에서 빠름 | 안전하지만 느림 |

### 3.3 성능 지표 — 각 지표가 의미하는 것

#### 정착 시간 (Settling Time, Ts)
"명령을 내린 후 목표 위치에 도달하여 더 이상 흔들리지 않는 데 걸리는 시간."

정확히는, 실제 위치가 타겟의 ±1% 범위 안에 들어간 후 다시 벗어나지 않는 최초 시점입니다. 예를 들어 90° 스텝이면 ±0.9° 범위 안에 안착하는 시점.

**짧을수록 좋음.** 1초 이내면 일반적으로 양호.

#### 오버슈트 (Overshoot, OS)
"목표를 넘어서 갔다가 돌아오는 정도."

예: 목표가 90°인데 92°까지 갔다가 90°로 돌아옴 → 오버슈트 = 2/90 = 2.2%.

**낮을수록 좋음.** 10% 이하가 일반 기준, 2% 이하면 우수.

#### 정상상태 오차 (Steady-State Error, SSE)
"충분한 시간이 지난 후에도 남아있는, 목표와 실제의 차이."

```
예: "90°로 가라" → 실제 89.5°에서 멈춤 → SSE = 0.5°
```

이 오차에는 여러 원인이 합쳐져 있으며, 현재 실험 데이터만으로는 각각의 기여를 정확히 분리할 수 없습니다:
1. **센서 LUT 잔류 오차** — PCHIP 교차검증 결과 최대 0.62°. 특정 각도에서 센서 자체가 틀린 값을 보고함.
2. **코깅 토크** — BLDC 모터의 고유 특성으로, 각도에 따라 주기적 토크 리플 발생. 미측정.
3. **Voltage-mode 토크 비선형성** — 전류 센싱 없이 전압으로만 제어하므로, 위치별로 실제 토크가 달라짐. 구조적 한계.
4. **PID 잔여 오차** — 적분기(I)가 부족하면 수렴하지 못함.
5. **리플/노이즈** — 멈춘 상태에서도 미세하게 흔들림.

> [!IMPORTANT]
> **SSE가 위치에 따라 달라진다는 사실(0.00°~0.62°)**은 원인이 위치 의존적임을 뜻합니다. 위의 1~3번이 모두 위치 의존적이며, **이들의 개별 기여를 분리하려면 추가 실험(외부 기준 엔코더 동시 측정, 코깅 토크 맵 등)이 필요합니다.**
> 
> 다만, PID 수렴 능력 자체는 병목이 아닙니다. 근거: 같은 위치(HOME)로 반복 복귀 시 편차가 0.07°로, PID는 충분히 잘 수렴하고 있습니다.

#### 리플 (Ripple, pk-pk)
"정지 상태에서 위치 값의 흔들림 폭."

모터가 멈춰있어야 하는데 미세하게 떨리는 것. 센서 노이즈, 제어 루프의 미세 진동, 코깅 토크 등이 원인. **낮을수록 좋음.**

#### 반복성 (Repeatability)
"같은 위치로 돌아오라고 했을 때, 실제로 얼마나 정확히 같은 자리로 오는가."

이것은 SSE와 **다른 개념**입니다:
- **SSE (정확도, accuracy)**: "명령한 위치에 얼마나 정확히 도달하는가"
- **반복성 (정밀도, precision)**: "같은 명령을 반복했을 때 결과가 얼마나 일관되는가"

예: 매번 90° 명령에 89.5°로 가면 → SSE는 0.5°(나쁨)이지만 반복성은 0°(완벽). "틀리지만 항상 같은 만큼 틀림."

> [!TIP]
> **이 시스템에서 SSE보다 반복성이 훨씬 좋은 이유**: SSE의 주요 원인(센서 오차, 코깅)은 같은 위치에서 항상 같은 크기로 나타나는 **고정 바이어스**이므로, "같은 자리로 돌아가기"에는 영향을 주지 않습니다.

- 방향 비대칭 크게 해소 (Ts std 0.73s → 0.28s)
- 다만 I가 낮아 SSE가 0.97°로 R3보다 악화

**핵심 발견**: `output_ramp`과 `velocity_limit`이 **정착 시간의 진정한 병목**이었음. PID를 올리는 것보다 이 두 값을 올리는 것이 더 효과적.

## 4. 최종 검증: 반복성 테스트 (Tr) + 다이얼 게이지

### 4.1 테스트 목적

위치제어의 **무결성(integrity)**을 두 가지 관점에서 증명합니다:
1. **내부 데이터**: 200Hz 텔레메트리로 정착 시간, 오버슈트, 오차를 정량 분석
2. **외부 검증**: 다이얼 게이지를 모터축에 대고 물리적으로 위치 복귀 확인 — 센서를 거치지 않는 독립적 검증

### 4.2 테스트 시퀀스

`Tr` 명령은 다음 시퀀스를 자동 실행합니다 (총 29초, 약 5,800 샘플):

```
HOME(5s) → -90°(3s) → HOME(5s) → -180°(3s) → HOME(5s) → -270°(3s) → HOME(5s)
```

- **HOME (5초)**: 다이얼 게이지 눈금을 읽을 시간 확보. 처음 2초는 정착, 나머지 3초가 안정 데이터.
- **이동 (3초)**: 목표 각도까지 이동 후 유지. 스텝 크기가 점점 커짐 (90° → 180° → 270°).
- **음(-)방향**: 다이얼 게이지가 수직 위에 있으므로 아래쪽으로 회전.

#### SSE의 위치 의존성 — 무엇을 증명하고, 무엇은 아직 모르는가

**증명된 사실:**
- SSE가 위치에 따라 0.00°~0.82°로 크게 달라짐
- PID가 원인이라면 모든 위치에서 비슷해야 함 → **PID 수렴 능력은 병목이 아님**

**위치 의존적 오차의 가능한 원인들:**
1. **센서 LUT 잔류 오차**: PCHIP 교차검증 최대 0.62° (측정됨)
2. **코깅 토크**: BLDC 모터 고유 특성, 각도별 주기적 토크 리플 (미측정)
3. **Voltage-mode 토크 비선형**: 전류 센싱 없어 위치별 실제 토크가 다름 (구조적)

**아직 모르는 것:**
- 위 3가지 원인의 **개별 기여 비율**을 분리하지 못함
- LUT 잔류 오차(0.62°)와 최악 SSE(0.62°)가 우연히 일치하지만, 이것이 "SSE = LUT 오차"를 증명하지는 않음
- 개별 기여를 분리하려면: 외부 기준 엔코더 동시 측정, 코깅 토크 맵 측정 등이 필요

> [!WARNING]
> **SSE의 위치 의존적 성분은 PID 튜닝으로 줄일 수 없습니다.** 원인이 센서든 코깅이든, 모두 하드웨어/캘리브레이션 수준의 개선이 필요합니다.

### 5.3 공정능력지수 (Cpk) — 참고 지표

Cpk는 원래 **AIAG SPC Manual(자동차 산업 품질관리)**에서 정의한 제조 공정 지표입니다. "사양 한계 대비 산포가 얼마나 여유 있는가"를 나타냅니다. **서보 위치제어에 직접 적용하는 산업 표준은 아니며**, 시스템 능력을 직관적으로 보여주는 참고 지표로 사용합니다.

| 사양 범위 | Cpk | 시그마 수준 | 판정 |
|----------|------|-----------|------|
| ±0.5° | 0.36 | 1.1σ | ❌ 부족 |
| ±1.0° | 0.73 | 2.2σ | ⚠️ 부족 |
| **±2.0°** | **1.47** | **4.4σ** | ✅ **충분** (≥1.33) |

±1° 사양에서 Cpk가 부족한 이유: 특정 각도에서 위치 의존적 오차가 0.8°에 달하므로, ±1° 범위 내에 들어갈 여유가 부족. 이것은 PID가 아닌 **센서/모터의 물리적 특성** 개선으로 해결해야 합니다.

## 9. 중력보상 실험 (Gravity Compensation)

### 9.1 실험 목적

중력보상(Gravity Compensation)은 외부 하중(분동)에 의한 중력 토크를 모터가 정확히 상쇄하여 **분동이 어떤 위치에서든 "떠 있는" 상태**를 만드는 것입니다. 이를 통해:

1. **토크 출력 정확도** 검증 — 계산된 토크가 실제 물리적 토크와 일치하는가?
2. **Vq-토크 선형성** 분석 — 전압 모드에서의 비선형성 특성 파악
3. **다양한 부하에서의 안정성** — 10g~200g까지 일관된 성능 확인

### 9.2 실험 구성

```
     ┌──── 모터 ────┐
     │   (Vq 인가)   │
     └──────┬───────┘
            │ 축
        ┌───┴───┐
        │ 풀리  │  r = 20mm
        │(반경) │
        └───┬───┘
            │ 줄
           ┌┴┐
           │W│ 분동 (m·g)
           └─┘
    τ = m × g × r = 일정 (각도 무관)
```

> **왜 풀리인가?** 로봇 팔에서의 중력보상은 `τ = m·g·L·cos(θ)`로 각도마다 다른 토크가 필요하지만, 풀리에서는 `τ = m·g·r = 상수`입니다. cos(θ)가 사라져서 **순수 일정-토크 보상 능력**만 측정할 수 있습니다.

### 9.3 제어 방식: Voltage-mode FOC

```
                      FOC 정류 (로터 각도 기반)
                              ↓
  사용자 → Vq (전압) → [d-q 변환] → PWM → 모터 → 토크
                          ↑
                      엔코더 피드백
```

- **FOC 정류**: 로터 각도를 실시간 추적하여 최적 위상에 전압 인가 ✅
- **토크 루프**: 전류 피드백 **없음** — Vq를 직접 지정하여 간접 토크 제어
- 이것은 SimpleFOC의 `TorqueControlType::voltage` 모드
- 위치제어(m3)에서도 동일한 voltage 모드를 사용 (PID가 Vq를 조절)

### 9.4 캘리브레이션 과정

**1단계: G1 (50g) — Kt 초기 측정**
- `m5 50 20` → 초기 Kt=10mNm/V로 Vq=0.981V 자동 계산
- `g+`/`g-`로 미세 조정 → **균형점 Vq = 0.891V** 발견
- 실측 Kt = 9.81mNm / 0.891V = **11.01 mNm/V**
- 펌웨어에 Kt_cal = 0.01101 Nm/V 반영

**2단계: G2~G6 — 나머지 무게 검증**
- 각 무게에서 Vq를 조정하여 균형점 탐색
- `Tg` 명령으로 30초 × 200Hz 자동 로깅
- 손으로 분동을 올렸다 내리면서 "손 뗀 후 유지" 확인

### 9.6 Vq-토크 선형성 분석

![Gravity Compensation Analysis](docs/images/grav_comp_analysis.png)

**선형 적합 결과:**
```
τ = 36.26 × Vq − 20.68   (R² = 0.965)
```

- **R² = 0.965**: 선형 상관은 높지만, y-절편이 -20.68mNm으로 원점을 지나지 않음
- **원점 통과 적합**: τ = 19.56 × Vq (R² = 0.739) — 저토크 구간의 오프셋으로 적합도 저하
- **2차 적합**: R² = 0.983 — 약간의 비선형성이 존재

**원인**: Voltage 모드에서 실제 토크는 `τ = Kt × Vq / R`이지만, 저전압 구간에서 **코깅 토크**(~2mNm)와 **마찰**이 추가 보상 역할을 하여 필요 Vq가 낮아짐.

### 9.7 유효 Kt 분석

| 무게 | τ (mNm) | Vq (V) | Kt_eff (mNm/V) |
|------|---------|--------|----------------|
| 10g | 1.96 | 0.680 | 2.88 |
| 50g | 9.81 | 0.891 | 11.01 |
| 100g | 19.62 | 0.990 | 19.82 |
| 150g | 29.43 | 1.350 | 21.80 |
| 200g | 39.24 | 1.700 | 23.08 |

- 10g에서 Kt_eff = 2.88 mNm/V (코깅이 대부분 토크를 담당)
- 100g 이상에서 Kt_eff ≈ 20~23 mNm/V로 수렴 — **선형 영역**
- 이 수렴값은 `Kt/R = 31.5mNm/A ÷ R` 에서 R ≈ 1.4Ω 에 해당

### 9.8 Voltage vs Current 모드 비교

| 무게 | 필요 전류 (Iq=τ/Kt) | 실제 전류 (Vq/R) | 전류 효율 |
|------|-------------------|-----------------|----------|
| 10g | 0.062A | 1.36A | 4.6% |
| 50g | 0.311A | 1.78A | 17.5% |
| 100g | 0.623A | 1.98A | 31.5% |
| 150g | 0.934A | 2.70A | 34.6% |
| 200g | 1.246A | 3.40A | 36.6% |

> **Voltage 모드의 전류 효율은 5~37%** — 필요 이상의 전류가 흐름.
> Current 모드(foc_current)를 사용하면 동일 토크를 1/3~1/20 전류로 달성 가능.
> 이는 **300g 이상도 안전하게 보상 가능**함을 의미.

### 9.9 300g 실패 분석

```
τ_필요 = 300g × 9.81 × 0.02m = 58.86 mNm
I_필요 (current 모드) = 58.86 / 31.5 = 1.87A  ← 충분히 안전
I_실제 (voltage 모드) = Vq/R ≈ 2.4/0.5 = 4.8A  ← 4.5A 한계 초과!
```

**모터의 토크 능력 자체는 충분**하지만, voltage 모드의 전류 비효율로 인해 소프트웨어 안전 한계(Istall=4.5A)를 초과.

## 10. Full FOC 전류 제어 구현

### 10.1 문제 인식

기존 시스템은 `TorqueControlType::voltage` 모드로 동작했습니다. 이것은 FOC의 좌표 변환(Park/Clarke)은 사용하지만, 가장 핵심인 **전류 피드백 루프가 없는** 구조였습니다.

```
[기존] 사용자 → Vq(전압) → 역Park → PWM
                               ↑
                          엔코더만 사용

[변경] 사용자 → Iq*(전류) → [전류 PI] → Vq → 역Park → PWM
                              ↑                    ↑
                         전류 센서 (Ia,Ib)     엔코더
```

### 10.2 구현 내용

**이미 갖추어진 인프라:**
- DRV8316 내장 CSA (Current Sense Amplifier)

## 11. Voltage vs FOC Current — 정량 비교

이 섹션에서는 동일한 하드웨어(Maxon EC-i 460720 + DRV8316 + STM32G431)에서 **토크 제어 방식만 바꿨을 때** 성능이 어떻게 달라지는지를 정량적으로 비교합니다.

### 11.1 비교 조건

```
                    [공통]                      [차이]
하드웨어:           동일                        —
엔코더:            MAQ473 + PCHIP LUT          —
위치/속도 PID:     velP=0.3, velI=2.0, angP=6.0  —
토크 제어 방식:    —                           Voltage vs foc_current
전압 공급:         12V                         —
```

**Voltage 모드**: 속도 PID가 출력하는 Vq(전압)를 그대로 모터에 인가. 실제 전류(토크)는 회전 속도에 따른 back-EMF에 의해 변동.

**foc_current 모드**: 속도 PID가 출력하는 Iq*(전류 목표)를 전류 PI 제어기가 추적. 전류 센서(DRV8316 CSA)로 실제 Ia, Ib를 측정하고, Clarke-Park 변환으로 Id/Iq를 얻어 피드백. 속도와 무관하게 일정한 토크를 보장.

### 11.2 위치제어 성능

> [!IMPORTANT]
> 아래 비교는 **동일 PID 세팅**(velP=0.3, velI=2.0, angP=6.0) 기준입니다.
> 데이터 소스: Voltage Tp(260709-212129), Current Tp(260710-170613) — 각 6스텝 (±90°, ±180°).

| 지표 | Voltage 모드 | FOC Current 모드 | 변화 |
|------|------------|----------------|------|
| Overshoot (평균) | 1.7% | **1.0%** | ✅ -43% 감소 |
| SSE (평균) | 0.49° | 0.53° | ≈ 동등 (+10%) |
| Settling time (5%) | 0.411s | 0.637s | Current 55% 느림 |
| Ripple pk-pk (평균) | 2.47° | **1.23°** | ✅ **-50% 감소** |

![위치제어 스텝 응답 비교 — Voltage vs FOC Current](docs/images/pos_ctrl_comparison.png)

위 그래프에서 4개 스텝의 시간-변위 곡선을 직접 비교할 수 있습니다. 붉은 선(Voltage)이 정착 후에도 진동(리플)이 크고, 파란 선(Current)은 정착 후 안정적입니다.

**핵심 차이: 리플(Ripple) -50%**

Voltage 모드에서는 정착 후에도 전류가 back-EMF 변동에 의해 요동하여 **2.47° pk-pk 리플**이 발생합니다. Current 모드에서는 전류 PI가 이를 능동적으로 억제하여 **1.23°**로 절반 감소합니다.

**왜 오버슈트는 비슷한가?**

이 PID 세팅(velP=0.3, angP=6.0)은 원래 보수적으로 튜닝되어 있어 Voltage 모드에서도 오버슈트가 1.7%로 낮습니다. 더 공격적인 PID(예: velP>1.0)를 사용하면 Voltage 모드의 오버슈트가 급격히 증가하지만, Current 모드는 전류 PI가 토크를 일정하게 유지하므로 오버슈트 증가가 억제됩니다.

**왜 Current 모드가 더 느린가?**

Current 모드에서는 Iq 목표 → 전류 PI → Vq 출력의 **추가 제어 단계**가 있습니다. 이 내부 루프의 응답 시간(LPF Tf=0.001s)이 전체 정착 시간에 약간의 지연을 추가합니다. 그러나 이 대가로 정착 후 리플이 절반으로 줄어들어 **정적 정밀도**에서 이점을 얻습니다.

**정적 SSE는 왜 비슷한가?**

정지 상태에서는 back-EMF ≈ 0이므로 두 모드의 동작이 유사해집니다. 정적 SSE는 주로 **엔코더 분해능**(MAQ473 14-bit + LUT 보정)과 **외부 PID 게인**에 의해 결정됩니다.

### 11.4 선형성 심층 비교

**선형성(Linearity)**이란: 입력(Vq 또는 Iq)을 2배 늘리면 출력(토크)도 정확히 2배 늘어나는 성질. 로봇 관절에서 "50g을 버틸 수 있으면 200g은 4배 입력으로 버틸 수 있다"고 예측할 수 있어야 실용적입니다.

#### R² 비교 — 두 가지 기준

**R² (linear fit)**: 데이터에 최적 직선(y = ax + b)을 맞춘 적합도. 절편 b가 0이 아니어도 됨.

**R² (through-origin)**: 원점을 지나는 직선(y = ax)의 적합도. 물리적으로 "입력 0이면 토크 0"이어야 하므로 이 기준이 더 엄격하고 실질적입니다.

| 지표 | Voltage (5pt) | FOC Current (5pt) |
|------|-----------|-------------|
| **R² (linear fit)** | 0.9650 | **1.0000** (4pt excl 250g) |
| **R² (through-origin)** | 0.7392 | **0.9922** |

![선형성 비교 — 별도 축 시각화, 150g 추가](docs/images/linearity_corrected.png)

> [!NOTE]
> Voltage와 Current의 입력 단위가 다르므로(V vs A), **같은 x축에 그리면 시각적 착시가 발생**합니다. 위 그래프는 각 모드를 별도 패널에 그려 **y절편(원점 거리)**을 정확히 비교합니다:
> - **Voltage**: y절편 = **-20.7 mNm** (원점에서 크게 벗어남)
> - **Current**: y절편 = **+3.0 mNm** (원점에 거의 일치)
>

### 11.7 전류 효율 (I²R 발열)

**I²R 손실**: 전류가 모터 코일(저항 R = 0.766Ω)을 통과할 때 열로 소비되는 전력. `P = I² × R`. 같은 토크를 더 적은 전류로 달성하면 발열이 줄어들어 모터 수명과 안전성이 향상됩니다.

| 무게 | Voltage Irms | Voltage I²R | Current Iq | Current I²R | 발열 감소 |
|------|------------|-----------|----------|-----------|--------|
| 50g | 1.78A | 2.43W | 0.471A | **0.17W** | **-93%** |
| 100g | 1.98A | 3.00W | 1.150A | **1.01W** | **-66%** |
| 150g | 2.70A | 5.58W | 1.825A | **2.55W** | **-54%** |
| 200g | 3.40A | 8.85W | 2.500A | **4.79W** | **-46%** |
| 250g | — | — | 3.000A | **6.90W** | — (Voltage 미실험) |

> **왜 Current 모드가 효율적인가?**
>
> Voltage 모드에서는 Vq를 인가하면 **Id(자속 방향)와 Iq(토크 방향)** 양쪽에 전류가 흐릅니다. Id는 토크를 생산하지 않고 열로만 소비됩니다. Current 모드는 **Id ≈ 0**으로 제어하여 Iq(토크 방향)에만 전류를 집중시킵니다. 이 "Id = 0 제어"가 FOC 전류 제어의 핵심 원리입니다.
>
> **150g 추가 결과**: Voltage 5.58W → Current 2.55W로 **54% 감소**. 부하가 커질수록 효율 차이는 줄어들지만(93% → 54% → 46%), 어떤 부하에서도 Current 모드가 일관되게 우수합니다.

### 11.8 유효 Kt 비교

**Kt (Torque Constant, 토크 상수)**: 1A의 전류가 생산하는 토크. 데이터시트 값은 이상적인 조건에서의 값이며, 실제 시스템에서는 마찰, 코깅, 측정 오차로 인해 유효 Kt가 낮아집니다.

```
데이터시트 Kt = 31.5 mNm/A (이상적)
실측 유효 Kt ≈ 16~21 mNm/A (나머지는 마찰/코깅으로 소비)
```

| | 50g | 100g | 150g | 200g | 250g |
|---|---|---|---|---|---|
| **Voltage Kt_eff** | 5.5 | 9.9 | 11.1 | 11.5 | — |
| **Current Kt_eff** | 20.8 | 17.1 | **16.1** | 15.7 | 16.4 (클램핑) |
| **Datasheet Kt** | 31.5 | 31.5 | 31.5 | 31.5 | 31.5 |
| *단위: mNm/A* | | | | | |

> **Current 모드의 Kt_eff(15~21)가 Voltage 모드(5.5~11.5)보다 2~4배 높음**: 동일 토크를 더 적은 전류로 생산. Voltage 모드는 Id(비생산 전류)에 에너지를 낭비하지만, Current 모드는 Id≈0으로 제어하여 **Iq 전체가 토크 생산에 기여**.
>
> **150g의 Kt_eff = 16.1 mNm/A**: 100g(17.1)과 200g(15.7) 사이에 자연스럽게 위치하여, Kt_eff가 고부하에서 ~16 mNm/A로 수렴하는 패턴을 확인합니다. 이는 마찰이 부하 대비 상대적으로 줄어들기 때문입니다.
>
> **Voltage 모드에서 Kt_eff가 극단적으로 낮은 이유**: Voltage 모드의 "전류"는 실제 Iq가 아닌 추정 Irms입니다. Id 성분이 상당 부분을 차지하므로, 같은 Irms에서 생산되는 유효 토크가 적습니다.

> [!NOTE]
> **데이터 커버리지**: Current 모드 5pt(50g~250g), Voltage 모드 5pt(10g~200g). 공통 포인트(50g, 100g, 150g, 200g)에서 직접 비교 가능하며, 나머지는 각 모드의 극단 영역 데이터입니다.
